# Repères formateur — NOVA

## Préparer
Durée complète : 14 heures hors pauses. Quatre séquences de 145 minutes ; socle 60 minutes, corpus 45 minutes, tests transverses 75 minutes, fil rouge 80 minutes.
Vérifier avant la séance : compte professionnel, Agent Builder ou Studio standard, capacité réelle d'exécution, Knowledge, droits de partage et compte test pour les permissions. Ne pas autoriser un achat, un élargissement des droits ou une authentification anonyme pour terminer un TP.
Tous les participants construisent les quatre configurations. En animation distribuée, faire tourner opérateur et relecteur ; vérifier que chacun peut reproduire les manipulations.

## Enseigner les distinctions essentielles
Instructions ≠ droits ; source nommée ≠ source connectée ; génération de tableau ≠ modification Excel ; brouillon ≠ décision ; test conçu ≠ test réussi ; partage agent ≠ autorisation documentaire ; réponse sans résultat ≠ preuve d'habilitation ; un réglage de priorisation des sources ≠ blocage absolu des connaissances générales.

## Corrigé chiffré
BAC 240 000 EUR HT, réserve 20 000 incluse. AC 144 000, ETC 108 000 : EAC 252 000 ; dépassement +12 000, +5 %. Pas d'ajout de réserve une seconde fois. 30/40 = 75 % de réussite ; 40/60 = 66,7 % d'exécution. Retard fournisseur 30/04 -> 14/05 : 14 jours calendaires. EV/PV absents : pas de CPI/SPI. Risques R01 16 élevé ; R02 15 élevé ; R03/R04 12 modéré. Date de production baseline 07/06 ; D07 propose 21/06 et 260 000 sans décision. AN-017 ouverte et bloquante ; propriétaire de correction non nommé.

## Pédagogie de la correction
Ne pas donner le corrigé dans le prompt initial. Conserver la première réponse. En cas d'erreur, vérifier source/état/droits avant d'ajouter des consignes. Modifier une seule cause, versionner et rejouer en session neuve. Au moins une amélioration par agent doit être documentée ; si aucune erreur n'est observée, améliorer une sortie insuffisamment lisible et montrer que les tests restent réussis, sans inventer une panne.

## Sécurité de la simulation
TR-02 : note synthétique fournie au modèle, vérifie un comportement de non-reprise publique, pas une vraie habilitation. Le modèle ne doit pas répéter le témoin même dans un refus. TR-03 : choisir un nouveau témoin dans un fichier synthétique isolé en SharePoint, en référence et non embarqué ; A autorisé et B non autorisé, avec accord administrateur. Ne pas donner la valeur à B ni dans les sources publiques. Contrôler l'accès direct source avec les deux comptes. Si impossible : non exécuté, périmètre de validation limité.

## Validation
Les 24 fiches métier et les 4 fiches transverses détaillées sont dans le cahier. La grille comporte 40 lignes initiales car les transverses sont déclinés sur les quatre agents. Dupliquer pour les deux essais minimum des cas critiques et de robustesse transversale ; garder tous les essais. Si TR-03 est mutualisé, documenter très précisément ce que la preuve couvre.
Réussite pédagogique proposée : 80/100 et aucun défaut bloquant. Tests non exécutés ne valent jamais réussites. Une préparation sur papier sans accès n'est pas une création d'agent. Une validation de formation n'est pas une homologation ni une autorisation d'usage sur données réelles.

## Livrable final
Backlog PO -> exigences et recette AMOA -> plan/risques/arbitrage chef de projet -> dossier COPIL PMO. Transfert manuel par paquet relu, avec IDs et sources originales ; aucune orchestration automatique n'est présumée. Vérifier au moins une chaîne B04 -> US-04 -> exigence d'accès -> test négatif -> R02 -> action/escalade et décision à demander.

Les corrigés détaillés des douze exercices et les attendus de chaque test figurent dans le cahier pour garder un TP autonome. Les blocs HTML dépliables peuvent être affichés en clair par certains lecteurs Markdown : prévenir les participants.
